# Consolidated experiment data

This is the sole published result set for HeteroRAG: **6,000 main outcomes, 600 distinct questions, and 14 retained failures**. The [project README](../../README.md) explains the system, findings, and limitations.

| Phase | Conditions | Questions per condition | Outcomes |
|---|---:|---:|---:|
| `routing_fusion` | 12 | 300 | 3,600 |
| `link_access` | 8 | 300 | 2,400 |

The link-access phase contains 1,200 visible-link controls and 1,200 hidden-link outcomes. Keeping both arms enables paired measurement of the intervention. The phases have disjoint question IDs and were executed sequentially. Do not pool their accuracy estimates.

## Files

| File | Contents |
|---|---|
| `experiment.json` | Main cohort IDs, conditions, graph coverage, scope, and source bundle identities |
| `outcomes.csv` | One row per question-condition outcome, including failures |
| `condition-metrics.csv` | The 20 phase-specific condition summaries |
| `paired-comparisons.csv` | Paired effects and original 95% source-table bootstrap intervals |
| `graph-strata.csv` | Condition means for covered/uncovered source tables |
| `analysis.json` | Original main-phase statistics, link-access interaction, labeled post-hoc diagnostics, and failure identities |
| `evidence-traces.jsonl` | Compact route probabilities, selected stores, packed source IDs, citations, SQL status, and evidence hashes for every outcome |
| `provenance.json` | Original input, report, source-code, dependency, and model hashes |
| `manifest.json` | SHA-256 hashes of the eight data files and the export verification statement |

No pilot, smoke, validation, or repeated timing outcomes are included. Full retrieved contexts, service logs, and caches remain outside the public package.

## Outcome fields

- Identity: `experiment`, `phase`, `condition`, `question_id`, `table_id`, `job_id`. `source_phase` is always `evaluation`.
- Intervention: `postgres_links` is `visible` or `hidden`. In first-phase conditions that do not use PostgreSQL, `visible` describes the phase's configured access regime rather than a PostgreSQL call.
- Answer: `question`, `prediction`, `reference`, `em`, `f1`, `status`, `failed_stage`, `abstained`, and `empty_evidence`. Per-outcome scores range from 0 to 1; aggregate scores use percentages. Failed outcomes score zero.
- Routing: `option` is the effective route, `raw_option` is the original proposal when present, and `selected_stores` is a count. The trace file provides store names and probability arrays. A failed route may have no final decision.
- Coverage: `graph_covered_snapshot` describes the original table-coverage snapshot. `graph_covered_observed` is populated when that retrieval observed graph availability. Coverage does not establish answer correctness or graph necessity.
- Requests: `data_requests` counts application data operations. Control operations, connection attempts, Decisions calls, and per-store counts are separate. `replayed_route` and `retrieval_replayed` identify reuse. Zero replay requests are not a production savings estimate.
- Evidence: candidate counts, text-byte estimates, fetch IDs, context tokens, and packed item counts. `pinecone_response_bytes_estimate` is estimated serialized payload size, not total network transfer or billing.
- Timing: seconds for service, retrieval, routing, and answer stages. They are descriptive and do not substitute for a controlled latency comparison.
- Provenance: `source_result_sha256` is the original checkpoint file hash. Trace hashes preserve original candidate, ranking, and reader-context identities without redistributing full contexts.

Empty CSV cells represent missing or inapplicable values, not zero. `True`/`False` cells are booleans serialized by the original reporting code. Preserve question pairing and the original condition labels when analyzing the data.

## Verification

From the repository root:

```bash
python -m tools.experiment verify
python -m tools.experiment summarize
```

The verifier uses local files and the Python standard library. It checks hashes, the full 6,000-outcome Cartesian design, disjoint cohorts, all answer scores, graph coverage, failure counts, means, paired point estimates, and link-access interactions. Bootstrap intervals are preserved from the original main reports, not regenerated by this command.

Questions and reference answers originate from [HybridQA](https://github.com/wenhuchen/HybridQA). See the [project attribution](../../README.md#data-and-attribution) and [evaluation guide](../../docs/evaluation.md) for scope and provenance.
